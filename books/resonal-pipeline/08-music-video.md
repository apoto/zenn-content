この章では、マスター音源・カバー画像・歌詞から、歌詞が出るMV（本編・ショート・サムネイル）を作る工程を説明します。公開版では `./tools/make_mv.sh` を1回実行すると、文字起こしからレンダー、検査までが順に走ります。そのあと人が動画を見てOKを出すまでが、この工程です。

## Remotionとは

MVはRemotionで作っています。Remotionは、Reactのコンポーネントとして書いた画面を、1フレームずつ描いて動画にするライブラリです。コンポーネントは「今が何フレーム目か」を受け取り、その時点の画面を返します。時間を引数にした関数として画面を書く、と考えると分かりやすいと思います。

![](/images/resonal-pipeline/remotion-code.jpg)
*RESONALのMVの画面。左がコード、右がRemotion Studioのプレビュー。*

この形にしているのは、AIがコードを書き換えるだけで動画を直せるためです。また、同じコードからは同じ動画が出るので、直した箇所以外が変わっていないことも確かめやすいです。公開版のテンプレート（`templates/mv/`）はRemotion 4で、1つのプロジェクトから本編（`LyricVideo`・1920×1080）、ショート（`ShortVideo`・1080×1920）、サムネイル（`Thumbnail`）の3つを書き出します。

## make_mv.shを1回実行する

MVの工程では、AIが次のコマンドを1回実行します。

```bash
./tools/make_mv.sh "songs/<曲フォルダ>"
```

前提として、曲フォルダにマスター `<Title>.wav`（「マスタリング」の章）、`LYRICS.md`（「作詞」の章）、横長の `cover.png`（「作曲」の章）が必要です。初回は `templates/mv/` を `projects/<slug>/` にコピーして `npm install` し、2回目以降は同じプロジェクトを使います。

![make_mv.shの中の流れ](/images/resonal-pipeline/mv-pipeline.png)
*make_mv.shの中で走る工程。番号の順に実行する。*

中では、次の順にスクリプトが走ります。

| # | スクリプト | やること |
|---|---|---|
| 01 | `01_transcribe.sh` | Whisperで歌を文字起こしし、語ごとの秒を取る |
| 02 | `02_tempo.sh` | テンポ（拍の位置）と、音の強さ `energy.json` を測る |
| 03 | `03a` / `03b` / `03c` | 背景・前景（キャラ）・背景ループ動画を用意する |
| 04 | `04_build_lyrics.py` | `LYRICS.md` の文言とWhisperの秒から `lyrics.json` を作る |
| 05 | `05_render.sh` | 本編・ショート・サムネイルを書き出す |
| 06 | `06_verify.sh` | 書き出した動画が壊れていないかを検査する |

各段は、成果物ができたことを確かめてから次へ進みます。途中で止まったら、AIが表示された `[NG]` の行を直して同じコマンドを再実行します。文字起こしが済んでいれば01は飛ばします。文字起こしとレンダーには数十分かかることがあるので、AIは長い処理をバックグラウンドで走らせて待ちます。

## 01文字起こし — Whisperで語ごとの秒を取る

最初に、音源をWhisperで文字起こしします。WhisperはOpenAIが公開している音声認識モデルで、ローカルで動かせます。公開版ではopenai-whisperのCLIをmediumモデルで使い、`--word_timestamps True` で語ごとの秒も出します。言語は `song.json` の `lyrics_lang`、無ければ `workflow.config.json` の `lyricsLang` で決めます。英語詞の曲を日本語として文字起こしすると、語の秒がずれるためです。

Whisperはモデルの取得に失敗しても終了コード0を返すことがあるので、最後に出力のJSONが空でないかを確かめます。

## 02テンポとenergyを実測する

### テンポは、発注値ではなく音源から測る

カメラの切り替えを拍に合わせるには、BPMと最初の拍の位置が必要です。ここでは、生成のときに指定したBPMではなく、できあがった音源から測った値を使います。RESONALでは、BPM 122で発注した曲を測ると126.05でした。Bubble Troubleのように、曲の途中で136.2から138.4 BPMへ少しずつ速くなる曲もありました。

`02_estimate_tempo.py` は、低い周波数を重く見たスペクトルの変化量（キックが鳴った瞬間に大きくなる値）を作り、区間ごとにBPMと最初の拍の位置の組み合わせを総当たりして、拍の位置で値が大きくなる組を選びます。高い周波数（ハイハットやクラップ）でも同じ推定をして、BPMの差が0.3を超えたら警告します。結果は区間ごとの `tempo.json` と、それをつないだ拍の一覧 `beats.json` に書き出します。テンポが倍や半分に取れたときは、`make_mv.sh` に `--bpm <下限> <上限>` を付けて範囲を絞ります。

### energy.json — 映像を動かす2つの信号

`02_energy.py` は、映像を動かすための2つの信号を1フレームごとに作ります。`sec` は区間の強さで、フレームごとの音量（RMS）を2.5秒の窓で平均して0〜1に伸ばしたものです。サビで高く、落ちサビで低くなります。`hit` は打点で、音量が前のフレームより上がった量を0〜1に伸ばしたものです。この2つは、後で説明する自動の振り付けと見た目の型（style）が使います。

## 03背景・前景・背景ループ動画を用意する

`03a_prep_cover.sh` は、カバー画像から本編用（16:9）とショート用（9:16）の背景を作ります。前景（キャラクター）は、`profile/images/character.png` があるかどうかで作り方を変えています。

```bash:tools/make_mv.sh
"$T/03a_prep_cover.sh" "$SONG/cover.png"
CHAR="$REPO/profile/images/character.png"
# 立ち絵があればキャラを前景に、無ければカバーから被写体を切り抜く
if [ -s "$CHAR" ]; then "$T/03b_cutout_fg.sh" "$CHAR" --place
else "$T/03b_cutout_fg.sh" "$SONG/cover.png"; fi
```

立ち絵があれば、画面の高さの90% に収めて下端中央に置きます。無ければ、カバー画像から被写体を切り抜き、背景と同じ切り取り方で置きます。切り抜きには、画像の背景を取り除くPythonのライブラリrembgを、アニメ絵向けの `isnet-anime` モデルで使っています。背景と前景を分けておくと、キャラの後ろに光を置いたり、キャラの手前に文字を通したりできます。曲フォルダに `bg_loop.mp4` があれば、`03c_prep_loop.sh` が背景用のループ動画も用意します（後述）。

## 04歌詞同期 — 文言はLYRICS.md、秒はWhisperから取る

`04_build_lyrics.py` は、画面に出す文言を `LYRICS.md` の「## 歌詞（表示用）」から、それを出す秒をWhisperの出力から取っています。文言にWhisperの聞き取り結果を使わないのは、空耳が混じるためです。

![](/images/resonal-pipeline/whisper-timing.jpg)
*RESONALの曲でWhisperが測った語ごとの秒。「タ・タ・タップ」も0.16秒刻みで分かれる。*

「歌詞（表示用）」の1行が画面の1フレーズで、行末に `{drop}` などを書くと、その行の見せ方が変わります。

### 文字単位で対応付けて、順番が合わない行を外す

歌詞とWhisperの文字列をそれぞれ正規化し（全角半角を揃える、カタカナをひらがなにする、記号を除く）、Pythonの `difflib` で順番を保ったまま文字単位で対応付けます。`LYRICS.md` に同じ行数の「## 歌詞（かな版）」節があれば、Whisperがかなで返した行を拾うために、それも対応付けに使います。

次に、対応付けの外れを除きます。曲の頭から時刻が増え続ける行の組をできるだけ多く残し、順番が合わない行を1行ずつ外します。繰り返すサビで、別のサビの位置に誤って一致した行を除くためです。

### 拾えない行は、前後の行から割り振る

対応付けできなかった行は、前後の対応済みの行のあいだを文字数の比で割り振り、どの行を割り振ったかを一覧で表示します。

Whisperは、歌の無い部分や聞き取りにくい部分で、実際には無い言葉を返すことがあります。RESONALのCotton Overkillでは、曲の最後のサビの繰り返しを文字起こししたところ、「ご視聴ありがとうございました!」が返ってきました。こうした行は歌詞と一致しないので、割り振りの対象になります。

対応付けできた行が60% 未満のときは、`LYRICS.md` が実際の歌と違うとみなして、`lyrics.json` を書かずに止まります。掛け声が多い曲などで止まったときは、AIがその行を伝え、了承をもらってから `--allow-unaligned` を付けて実行し直します。

## 歌詞の秒を仕上げて、文字の大きさを決める

### 語の頭に吸着させ、間奏では画面を空ける

各行の開始の秒は、Whisperの語の開始秒（オンセット）のうち、0.7秒以内で最も近いものに合わせ直します。

```python:templates/mv/tools/04_build_lyrics.py
        t = ph["t"]
        i = bisect.bisect_left(onsets, t)
        cands = [onsets[j] for j in (i - 1, i, i + 1) if 0 <= j < len(onsets)]
        if not cands:
            continue
        near = min(cands, key=lambda o: abs(o - t))
        if abs(near - t) <= tol and near != t:
            changes.append((t, near, ph["text"]))
            ph["t"] = round(near, 3)
```

RESONALでこの処理を足す前は、Whisperの歌のまとまり（セグメント）の境界の秒だけを使っていて、1つのセグメントを2行に割った箇所で、大きいところでは1.68秒ずれていました。

表示する長さは、次の行が出るまでに伸ばします。ただし、次の行まで3.5秒を超えて空いているときは、歌の無い間奏とみなして、字幕を出しっぱなしにせず画面を空けます。最後に、前の行の表示が次の行に重なっていないかを検査し、重なっていれば止まります。

### 行の幅から、文字の大きさの上限を決める

字幕は折り返さない設定なので、長い行を大きな文字で置くと画面の外にはみ出します。そこで、行ごとに文字の大きさの上限を計算しています。

```python:templates/mv/tools/04_build_lyrics.py
def max_size(text: str) -> int:
    """本編と縦ショートの両方で画面幅の SAFE に収まる最大 px（縦は SHORT_SCALE 倍で描かれる）。"""
    w = max(0.5, visual_width(text))
    return int(min(COMP_16 * SAFE / w, COMP_9 * SAFE / (w * SHORT_SCALE)))
```

行の幅は、全角を1.0、半角を0.55、空白を0.35として足し合わせて見積もります。そこから、本編（幅1920px）とショート（幅1080px）の両方で、画面幅の86% に収まる大きさを出します。上限が64pxを下回る行は、`LYRICS.md` で行を割るよう警告します。

## 05レンダーと06検査

`05_render.sh` は、最初に設定ファイルからタイトル・クレジット・見た目の型を読み込みます。次に、マスター `<Title>.wav` をMVのプロジェクトへコピーし、歌詞データに書いた曲の長さと実際の音源の長さが0.5秒を超えて違えば止まります。

そのうえで、ショート → 本編 → サムネイルの順に書き出し、曲フォルダに `<Title>.mp4`・`<Title> (Short).mp4`・`thumbnail.jpg` として置きます。レンダラは素材が欠けていても終了コード0を返すことがあるので、書き出すたびに、ファイルがあることと尺をffprobeで確かめます。

`06_verify.sh` は、書き出した動画を最後までデコードして、エラーが無いかを確かめます。RESONALで、ディスクの空きが足りなくなったときに、レンダラがエラーを出さずに一部が壊れたmp4を書き出し、サムネイルや数枚の静止画では気付けなかったことがあったためです。あわせて、`credits` が画面に出るようになっているかも確かめます。`providers.notify` を `slack` にしていれば、最後にSlackにも送ります。

## 振り付けは、音の強さから自動で決める

カメラの動きや光の演出は、`input/song.config.ts` が曲の長さ・拍・音の強さから自動で決めています。手で書かなくても動きます。

まず、拍の一覧から小節を作り、8小節ごとに区切って、その区間の `sec` の平均で強・中・弱に分けます。

```ts:templates/mv/input/song.config.ts
  return edges.slice(0, -1).map((start, i) => {
    const end = edges[i + 1]; const e = meanEnergy(start, end);
    return { start, end, level: e >= 0.62 ? 'high' : e < 0.35 ? 'low' : 'mid' };
  });
})();
const HIGH = SECTIONS.filter((s) => s.level === 'high');
const DROPS = SECTIONS.filter((s, i) => s.level === 'high' && i > 0 && SECTIONS[i - 1].level !== 'high').map((s) => s.start);
```

この区分けから、次のものを決めます。

- カメラ：4小節ごとにカットを割り、寄る位置を順に振ります。強い区間ほど揺れと跳ねを大きくします
- ドロップ：強くない区間から強い区間に上がる頭をドロップとし、直前の2小節で吸い込むような光を入れ、ドロップの直前で画面を白く飛ばします
- 光：強い区間は明るく、弱い区間はゆっくり呼吸するような光にします
- ショート：最初のドロップの2小節前から約30秒を切り出します。ドロップが無ければ、最も強い区間から切り出します
- クレジット：歌の無い冒頭か末尾のうち、長いほうに等分で置きます

自動で決めた値が合わないときは、このファイルの値を書き換えて `make_mv.sh` を再実行します。例えば `short: { start: 45, end: 75 }` でショートの区間を固定したり、`dropHits` にサビ頭の秒を足したりします。プロジェクトの中で `npx remotion studio` を実行すると、プレビューを見ながら詰められます。

## 背景を動かす動画素材は任意

背景を静止画ではなく、少しだけ動くループ動画にすることもできます。どのサービスで作るかは `workflow.config.json` の `providers.video` で選び、`none`（既定・作らない）、`kling-mcp`（推奨）、`other`（`note` に書いた手順で作る）から選べます。

Klingは画像や文章から動画を作るサービスで、公式のMCPサーバーがあるので、Claude Codeから直接呼び出せます。生成は課金の対象なので、AIは作る前に「cover.pngから約5秒のループ動画を1本作ってよいか」を聞きます。1回に1本だけ投げ、失敗したら投げ直すかを利用者に決めてもらいます。

ループにするために、始点の画像と終点の画像の両方に `cover.png` を渡します。始点と終点の絵が揃っていると、継ぎ目が見えないためです。プロンプトでは大きな動きをさせず、髪・光・粒子などの小さな動きだけを書きます。RESONALでは以前、順再生と逆再生をつなぐ往復のループも使っていましたが、僕が「ピンポンループは基本的に使えません」と伝えてからは、始点と終点を揃える方法にしています。

できた動画は曲フォルダに `bg_loop.mp4` として置きます。動画になるのは前景の後ろの背景だけで、前景とサムネイルはカバー画像のままです。`bg_loop.mp4` を外して再実行すれば静止画に戻ります。

## 人が見て、直し方のパターンで直す

レンダーと検査が通ると、AIは本編・ショート・サムネイルのパスを並べて、「見て、OKか、直したい点を教えてください」と頼んで止まります。ここは人の番です。

直したい点を聞いたら、AIは直し方を2〜3案示し、選んでもらってから直します。よくある直し方は、skill `music-video` に表でまとめています。

| 直したい点 | 直し方 |
|---|---|
| 歌詞のタイミングがずれる | `LYRICS.md` の「歌詞（表示用）」で行の切り方を変えて、秒を取り直す |
| 文字が大きい・小さい・はみ出す | 長い行を2行に分ける（文字の大きさは行の長さから決まる）／文字サイズの設定を変える |
| 読みにくい・色を変えたい | 縁取りや影を強める／背景を暗くする／配色を変える |
| 背景・キャラを変えたい | `cover.png` を差し替える／切り抜きを作り直す／背景を動かす・止める |
| クレジットの文言 | `workflow.config.json` の `credits` を直す |

直したら `make_mv.sh` をもう一度実行し、直した箇所のフレームをAIが抜き出して確認してから、もう一度見てもらいます。往復は何度でもかまいません。OKが出たら、AIが `song.json` の `approved_at` に日付を入れ、`./next.sh` はこの日付を見てMVの工程が終わったと判定します。

## 見た目の型は1つ

公開版に入っている見た目の型（style）は、`src/styles/neonnoir.tsx` の1つです。色はファイル冒頭の `PZ` で塗り替えられ、フォントはGoogle Fonts（OFL）を読み込んでいます。コードは、カメラ・合成・クレジットを担う `src/engine/` と、フォント・配色・字幕・装飾を担う `src/styles/` に分けています。

新しい見た目を増やしたい方は、`src/styles/<name>.tsx` に型を書いて `registry.ts` に登録し、`workflow.config.json` の `mv.look` をその名前にすれば切り替わります。RESONALで使ってきた13の見た目の型も、リポジトリの `styles/` に実験的に入れています。「MVの見せ方を選びたい」と話しかけると、AIがskill `mv-styles` で選ぶ手伝いをします。詳しくは「RESONALの場合」の章で紹介します。

## まとめ

MVの工程では、`make_mv.sh` を1回実行すると、文字起こし、テンポと音の強さの実測、背景と前景の用意、歌詞の同期、レンダー、検査までが順に走ります。歌詞は文言を `LYRICS.md` から、秒をWhisperから取り、カメラや光、ショートの区間は8小節ごとの音の強さから自動で決めます。最後に人が動画を見て、直し方のパターンで直し、OKが出たら `approved_at` を入れて次の工程に進みます。
