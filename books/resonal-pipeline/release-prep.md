---
title: "リリース準備 — 素材と文面を揃える"
---

この章では、MVのOKが出た後に、アップロードに使う素材と文面を揃える工程を説明します。公開版では `tools/release_prep.sh` が素材と文面の下書きを作り、AIが文面を整え、アップロードは人がチェックリストに沿って手で行います。作るものは、セットアップで選んだリリース先で決まります。

## release_prep.shが作るもの

リリース準備の工程では、AIが次のコマンドを実行します。

```bash
./tools/release_prep.sh "songs/<曲フォルダ>"
```

曲フォルダの `release/` に、選んだリリース先の分だけ、次のファイルができます。「リリースしない」を選んだ場合は、何も作りません。

| ファイル | 中身 | 作るリリース先 |
|---|---|---|
| `jacket_3000.jpg` | ジャケット（3000×3000） | 配信サービス・その他 |
| `thumbnail.jpg` | YouTubeのサムネイル | YouTube |
| `youtube.txt` | YouTubeのタイトル・説明文の下書き | YouTube |
| `dsp.txt` | 配信サービスに入力する曲情報の下書き | 配信サービス |
| `UPLOAD-CHECKLIST.md` | 人がアップロードする手順のチェックリスト | すべて |

ジャケットは、`cover.png` の中央を正方形に切り出して、3000×3000に拡大します。カバーの短辺が1500pxより小さいときは、大きく拡大したことを警告します。サムネイルは、MVの工程で作った `thumbnail.jpg` をそのまま使い、無ければ本編の3分の1の位置から1枚を抜き出します。

`youtube.txt` と `dsp.txt` には、設定ファイルのアーティスト名とクレジット、`LYRICS.md` の「歌詞（表示用）」を埋めた下書きを書きます。歌詞は、行末の `{drop}` などの記号を除いてから入れます。文面のファイルは、既にあれば上書きしません。AIや人が整えた文面を、再実行で消さないようにするためです。一方で、画像は `cover.png` のほうが新しければ作り直します。

## AIが文面を整えて、[下書き] 行を消す

下書きの先頭には `[下書き] 文面を整えたらこの行を消す` という1行が入っています。AIはskill `release-prep` の手順に沿って文面を整え、書き終えたらこの行を消します。

`youtube.txt` では、BRIEF.md・LYRICS.md・`profile/` の世界観や歌い手の設定を読んで、次のものを書きます。

- タイトル：`<Title> / <アーティスト名>` を基本に、利用者の好みの形式があればそれに合わせます
- 説明文：冒頭2行に曲の一言紹介、続けてクレジット、歌詞、使った生成AIの明記を並べます
- タグ：ジャンル・ムード・ユニット名・歌い手名を中心に10〜15個です

`dsp.txt` には、曲名・アーティスト名・作詞・作曲・ジャンル・言語・歌詞の有無・露骨な表現の有無・発売日を並べます。発売日は人が決めるので、空欄にして利用者に聞きます。作詞・作曲の名義がセットアップで「未定」のままなら、ここで聞き直します。

`./next.sh` は、この `[下書き]` 行で文面が整ったかどうかを判定しています。

```js:engine/steps.js
      // 雛形は先頭に [下書き] 行を持つ＝AI が文面を整えたら消す
      const draft = texts.filter((f) => /^\[下書き\]/.test(c.read(c.file(path.join('release', f))) || ''));
      if (draft.length) return ai(`${draft.join(' / ')} が下書きのまま`, '文面を整え、先頭の [下書き] 行を消す');
```

`texts` は、リリース先に合わせて `youtube.txt` と `dsp.txt` から選んだ一覧です。ファイルがあるだけでは工程が終わったことにならず、AIが文面に手を入れたことを1行で確かめる形にしています。ジャケットを作るリリース先では、`jacket_3000.jpg` が3000×3000であることも画像のサイズを読んで確かめます。

カバーは横長なので、ジャケットは中央を切り出して大きく拡大することになり、端が切れたり細部が甘くなったりします。そのときAIは「このまま使う」か「正方形で描き直す」かを利用者に聞きます。ジャケットやサムネイルに別の画像が要るとき（正方形で描き直したい、サムネイル専用の絵がほしい、など）は、`tools/gen_image.sh` で作ります。どのサービスで作るかは `providers.image` で選んだものに従います。作る前に、AIが利用者に聞きます。

## 作詞作曲の名義とAI使用の申告は、規約を確認する

作詞・作曲のクレジットをどう書くか、AIを使ったことをどう申告するかは、配信サービスやディストリビューターごとに規約が違います。そのためskillには、AIは書き方を断定せず「使う配信サービスの最新の規約で、作詞作曲の名義とAI使用の申告方法を確認してください」と伝える、と書いています。

`dsp.txt` の下書きでも、AI生成の開示の欄は「配信サービスの規定に沿って記入」として空けています。YouTubeについても、チェックリストに「改変または合成されたコンテンツ」などのAI開示の項目を確認する行を入れています。

## アップロードは人がチェックリストで行う

アップロードと公開は、利用者が自分のアカウントで手で行います。AIは、貼るだけの文面とファイルを揃えるところまでを担当します。

`UPLOAD-CHECKLIST.md` には、選んだリリース先の節が入ります。

- YouTube（本編）：`<Title>.mp4` をアップロードし、説明文に `youtube.txt` を貼り、サムネイルを設定し、AI開示の項目を確認して公開日時を決める
- YouTube（ショート）：`<Title> (Short).mp4` をアップロードし、説明文に本編へのリンクを入れる
- 配信サービス：ディストリビューターに `<Title>.wav` と `jacket_3000.jpg` を渡し、`dsp.txt` から曲情報と歌詞を入力し、AI利用の開示と権利情報を入れてリリース日を決める
- その他：設定に書いたリリース先に、`<Title>.wav` と `jacket_3000.jpg` を使って公開する
- SNS：告知文を書いて投稿する

AIは、このチェックリストを上から1項目ずつ読み上げて、利用者と一緒に確認します。直したい点があればその場で直し、文面を見せて「この内容でよいか」を聞いてから終えます。最後に `./next.sh` が終了コード0を返すことを確かめ、どのファイルを使ってアップロードすればよいかを、選んだリリース先の分だけ伝えます。

```
リリースの準備ができました。
- YouTube: release/youtube.txt の文面と <Title>.mp4・thumbnail.jpg を使ってアップロードしてください
- 配信サービス: release/dsp.txt の情報と <Title>.wav・jacket_3000.jpg を使って申請してください
アップロードと公開の操作はご自身でお願いします。
```

## ledgerに1行あるか確かめる

チェックリストの最後には、「公開後、`profile/ledger.md` にこの曲の1行があるか確認」という項目を入れています。ledgerは作った曲の一覧で、1曲1行でタイトル・テンポ・ジャンル・ムード・一行コンセプトを書きます。企画の工程でAIが次の曲の案を出すとき、直近の曲と被らないように読む表です。

行は企画の工程でAIが足し、MVの工程で実測したテンポに書き換えています。リリース準備では、その行が残っているかを最後に確かめます。`./next.sh` も、6工程が終わったときに「`profile/ledger.md` にこの曲の1行が無ければ足す」と表示します。

## まとめ

リリース準備では、`release_prep.sh` がジャケット・サムネイル・説明文と曲情報の下書き・チェックリストを `release/` に揃えます。AIは文面を整えて `[下書き]` 行を消し、作詞作曲の名義やAI使用の申告は各サービスの規約を確認するよう伝えます。アップロードと公開は、人がチェックリストに沿って自分のアカウントで行い、最後にledgerにこの曲の行があるかを確かめます。
