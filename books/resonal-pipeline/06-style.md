この章では、ミュージックビデオ（MV）の見せ方を、音源を作る前の段階でどう決めているかを説明します。工程の上では、この段階で Suno に渡す文章も書きますが、それは第7章でまとめて説明します。

## スタイルと軸

MV の見せ方は、「スタイル」と「軸」の2段階で決めています。

- **スタイル**：見せ方の型です。「白い図形と極太ゴシックの白黒反転」「黒と赤のゴシック」のように、書体・配色・動きの組み合わせに名前を付けたもので、2026年9月時点で13あります
- **軸**：MV を作るときに決める項目を、1つずつに分けたものです。歌詞の出し方、キャラクターの動かし方、背景、打点（音の強い瞬間に入れる演出）の4分類で、合計18あります

スタイルは、18の軸の値をまとめて決めたプリセットという位置づけです。スタイルを採用しても、軸は1つずつ選び直してよいことにしています。

どちらも Skill `mv-styles` にまとめています。スタイルの一覧は `references/catalog.md`、軸の選択肢は `references/axes.md` に書いています。

## 選定表：カタログ全件を1行ずつ評価する

新曲のスタイルを決めるときは、頭に浮かんだ1つで進めず、13のスタイルを1行ずつ評価した選定表を書いてから、採用1つと対抗1つに絞ります。僕が「新曲作成時にちゃんと選定検討されるよう注意して」と伝えたことから、`CLAUDE.md` のルールにしました。

選定表には、次の決まりがあります。

- 「使ったことがない」「Skill になっていない」は、落選の理由にしない
- 直近3曲で使ったスタイルを選ぶなら、理由を書く
- 対抗を落とした理由も1行書く

直近3曲について理由を求めているのは、惰性で同じスタイルに戻ることがよく起きるためです。また、過去に100個ほどの演出部品を集めたカタログを作ったものの、選ぶ手順に載っていなかったために1曲も使われなかったことがありました。選定表を書く手順は、カタログを使われないまま終わらせないための仕組みでもあります。

Stutter Step の選定表から、一部を抜粋・要約すると次のようになります。

| スタイル | 評価 | 理由（要約） |
|---|---|---|
| radial-wave | ✕ | 歌詞なしのビジュアライザで、文字で遊ぶという今回の要望と矛盾する |
| snaptype | ✕ | 静かで洗練された見せ方で、BPM 160 の連打と合わない |
| xerox | ○ 対抗 | 動きの文法は近いが、紙のざらつきの質感が今回の乾いた平面と合わない |
| negaposi | ◎ 採用 | 極太ゴシックを画面からはみ出させる、3色の反転、1文字ずつの連打がリグにある |
| tableau | ✕ | 背景動画が主役で、文字が主役の今回とは主従が逆。直近3曲でも使っている |

このときの直近3曲は、Bubble Trouble（sugarpop）、ある曲（ricochet）、Whiteout（tableau）でした。ricochet は動きとしては合っていましたが、直近で使っていたため採用せず、「跳ねて出現する」動きだけを一部の区間で借りています。

## 18の軸

軸は、僕が「①歌詞をどの出し方にするか ②キャラクターをどのように動かすか（パペット/ボーンリグ・静止画のみ・動画を生成してループ…）を切り分けたい」と伝えたことから作りました。キャラクターの動かし方をスタイルの中に作り込むと、他のスタイルの曲からは使えなくなるためです。そのため、キャラクターの動かし方は `puppet-rig` や `bounce-rig` といった部品の側に置き、どのスタイルからでも呼べるようにしています。

18の軸と、それぞれの既定値は次のとおりです。

| 分類 | 軸 | 既定 |
|---|---|---|
| 歌詞（L） | L0 レイヤー構成 | 単層 |
| | L1 配置 | 中央 |
| | L2 書体 | 極太ゴシック |
| | L3 出入り | ハードカット |
| | L4 装飾 | なし |
| | L5 帯（下のスクリム） | なし |
| キャラ（C） | C0 出すか | 出す |
| | C1 素材 | 静止画1枚 |
| | C2 動き | 呼吸のみ（拍とは非同期） |
| | C3 フレーミング | 固定のバストアップ |
| | C4 前景と背景の分離 | しない |
| | C5 表情の切り替え | 固定 |
| 背景（F） | F1 素材 | 静止画 |
| | F2 切り替え | なし |
| | F3 画面エフェクト | 常にうっすら1種 |
| | F4 カメラ | ゆっくり移動 |
| 打点（H） | H1 発火範囲 | ドロップ・サビだけ |
| | H2 抜き方 | 暗転 |

キャラクターの軸（C1・C2）は、コストが小さい順に検討します。静止画1枚、表情の差分、CSS で関節を動かすリグ、Kling（画像から動画を作る AI）で作る連番画像、の順です。Kling は1本ごとにクレジットを使うので、コードで作れない動きにだけ使います。

## 既定のままでも理由を書く

選定表を書いたら、18の軸を1つずつ埋めて `STYLE-SELECTION.md` に書きます。このとき、既定のままにする軸も省略せず、「既定」と理由を書くようにしています。

これは、「決めていない」と「既定を選んだ」を区別するためです。省略を許していた頃、打点の演出を曲の最初から最後まで入れていた曲がありましたが、それは選んだ結果ではなく初期値のままだったことが後で分かりました。

Stutter Step の軸表から、一部を抜粋・要約すると次のようになります。

| 軸 | 値 | 理由（要約） |
|---|---|---|
| C0 出すか | 出さない | 文字が主役の曲なので、キャラクターはサビなど要所だけで出す |
| F1 素材 | プロシージャル（コードで描く） | 背景は黒と蛍光イエローの平面なので、画像も Kling も要らない |
| F3 画面エフェクト | なし | 文字を読めることを優先する |
| H1 発火範囲 | ドロップ・サビだけ（既定） | サビ頭の反転を打点にし、Aメロでは入れずに落差を残す |

## 曲の既定値と、シーン別の上書き

`STYLE-SELECTION.md` に書く18軸は、その曲で最も多く使う値です。曲の最初から最後まで同じ値に縛るものではありません。

シーンごとに変える軸は、MV の演出設計書 `DIRECTION.md` の「シーン別の軸」節に、`軸コード=値` の形で書きます。変えない軸は書きません。記法は `axes.md` に次の例で示しています。

```markdown:.claude/skills/mv-styles/references/axes.md
## シーン別の軸（既定=STYLE-SELECTION.md・変える軸だけ書く）
| 区間 | シーン | 軸の上書き | レコード |
|---|---|---|---|
| 0:12–0:34 | Aメロ | F4=下→上（縦チルト） / F3=明るく（bloom） / L3=右→左へ流し | records/crane-shot, records/bloom-overexposure |
| 0:57–1:22 | サビ | L1=画面いっぱい（キャラ背面） / C1=動画素材 / C3=全身 / F3=キラキラ / H1=発火 | records/type-behind-subject, records/particle-rise |
```

「レコード」列は、演出ライブラリ（`mv-direction-library`）の中の、その演出の記録ファイルを指します。

この2段構えにしたのは、僕が「1シーン1シーンにも要素の掛け合わせで表現したい」と伝えたためです。実際、Whiteout では、カメラの軸を既定の「ゆっくり移動」にしたまま、シーンによってはカメラを寄せたり引いたり真上から撮ったりしていて、軸表が実際の MV を表せていませんでした。

## 機械で検査する

`next.sh` の STYLE 検査では、次の2点を確かめています。

1. カタログの全スタイル名が、選定表に出てくるか
2. 18の軸コードが、1つも欠けずに書かれているか

```js:release/checklist.js
      const AXES = ['L0','L1','L2','L3','L4','L5','C0','C1','C2','C3','C4','C5','F1','F2','F3','F4','H1','H2'];
      const noAxis = AXES.filter((a) => !new RegExp(`(^|[^A-Za-z0-9])${a}([^0-9]|$)`, 'm').test(md));
      if (noAxis.length) return `軸表に記入が無い軸: ${noAxis.join(', ')}`
        + `（全18軸を毎回検討する＝既定のままなら「既定」と書く。skill \`mv-styles\` の軸表）`;
```

スタイル名の一覧は、検査のコードには書かず、カタログのファイルから毎回読み込んでいます。そのため、カタログにスタイルを追加すると、検査の対象も自動で増えます。一方で、追加した日より前に選定を終えていた曲にまで新しいスタイルの評価を求めないよう、カタログの見出しに掲載日（`since 260827` など）を書き、それより後に企画した曲だけを検査しています。

シーン別の軸も、MV の工程に入ったところで DIRECTION 検査が確かめます。「シーン別の軸」節があり、軸コードが3種類以上書かれているか（どのシーンも既定のままなら「全編既定」と書かれているか）を見ています。

## まとめ

MV の見せ方は、13のスタイルを1行ずつ評価した選定表で型を決め、18の軸を1つずつ埋めて具体化します。軸は曲の既定値とシーン別の上書きの2段で書き、既定のままの軸にも理由を書かせることで、「決めていない」項目が残らないようにしています。
