---
title: "作詞 — 表示用とかな版の2つを書く"
---

この章では、歌詞をどう書いているかと、書いた歌詞を機械でどう検査しているかを説明します。作詞は AI（彩瀬??）の担当で、僕は書き上がった歌詞を読み、気になった点があれば返します。

## 流れ

作詞は、Skill `lyric-writing-jp` の手順に沿って次の順で進めます。

1. コンセプトを決める（何を、どの切り口で歌うか）
2. 深掘りインタビューで、歌の裏設定を決める
3. 歌の中の出来事を、先に小説として書く
4. 小説を削って、歌詞の初稿（v1）にする
5. 改稿ループで直す（v2、v3…）
6. `next.sh` の検査を通す

Skill の中身は、秋元康さんやつんくさんなど著名な作詞家のノウハウと、『作詞のための8の極意』（ヤマハミュージックメディア編）から抜き出した技法をまとめたものです。技法の細かい説明は Skill の参照ファイルに分けてあり、AI は該当する工程でそれを読み直します。

## 作詞の2つの縛り

RESONAL の作詞には、コンセプトの段階でかける縛りが2つあります。

### 主題は人の営み、語彙は別の装置から

1つ目は「営み × 装置」という書き方です。テーマには人間の営み（帰省・引っ越し・卒業・通勤など）を置き、それを描く語彙は、別の分野の具体的なもの（再放送・棚卸し・天気予報など）から取ります。この「別の分野」を Skill では装置と呼んでいます。

この縛りを足したのは、ある曲で装置の語彙だけを使って歌詞を書き、小道具の説明のようになってしまったためです。そこで Skill には「装置の語を外しても、営みが残るか」という検算を入れています。何も残らなければ、その歌詞にはテーマが無いと判断します。

### 指示語を使わない

2つ目は、「そっち」「こっち」「あっち」「あれ」「それ」「ここ」などの指示語を使わないことです。指示語は書き手の頭の中にしか像を作らず、聴く人ごとに違う場面を思い浮かべてしまうためです。

指示語を見つけたら、その場の具体的な名詞に置き換えます。Skill には「初見の人が読んで、場所・時刻・持ち物・視線の先が同じ絵になるか」という確認の仕方を書いています。

## 小説を書いてから、削って歌詞にする

歌詞を書く前に、2つの準備をします。

1つは深掘りインタビューです。「誰の視点か」「歌っている人は物語のどの地点に立っているか」「曲の前に何があったか」などの質問（必須は12問）に、AI が1行ずつ答えます。答えは曲フォルダの `INTERVIEW.md` に残します。

もう1つは、歌の中の出来事を小説として書くことです。音・匂い・手の動きなど、歌詞には入らない細部まで含めて2,000字前後で書き、`STORY.md` に保存します。そのうえで、削れない文に印を付け、Aメロ・Bメロ・サビに割り当て、説明や感情の名前を削って歌詞にします。

小説を先に書くのは、歌詞から書き始めると、空いた枠を言葉で埋めることになり、手癖が入るためです。物語が先にあれば、歌詞のどの行も小説のどこかの文に対応します。

## 改稿ループ

初稿（v1）はレビューの材料と考え、磨き込まずに最後まで書きます。そのあと、見る観点を1つずつ変えながら3回読み直します。

| ラウンド | 観点 | 主に見ること |
|---|---|---|
| 1 | 構造 | コンセプトがあるか、視点がぶれていないか、サビが結論になっているか |
| 2 | 音 | 全行を声に出して歌えるか、母音の流れ、韻の質 |
| 3 | 毒 | 語の出現回数、指示語、説明になっていないか、耳で聴いて意味が通るか |

各ラウンドでは、指摘を最低3件出します。指摘は「該当する行」「どの技法のどの違反か」「改稿案」の3点で書き、採用しなかった指摘にも理由を1行残します。

例えば Stutter Step では、Round 1 でサビの「言えないなら 踏めばいい」が、直前の「踏めばいいじゃん」と同じことを言っていると指摘し、「言えない分だけ 足が喋る」に直しました。Round 3 では「噛んだ音が そのまま 拍」の「はく」が、耳で聴くと「吐く」と区別できないと指摘し、「そのまま ビート」に直しています。

僕が読んで返すこともあります。同じ Stutter Step では、僕が「『噛んだ音がそのままビート』はちょっと直接的すぎる」と伝え、サビをスキャットのような言葉の刻みに書き換えてもらいました。

## LYRICS.md の構成

歌詞は、曲フォルダの `LYRICS.md` に次の節で書きます。

| 節 | 内容 |
|---|---|
| コンセプト | 一行コンセプト、切り口、語り手、モチーフ |
| 歌詞（表示用） | 漢字ありの本来の歌詞。MV や歌詞カードに使う |
| 歌詞（かな版） | 漢字をかなに開いた歌詞。Suno に入力する |
| メロディ・譜割りメモ | ブロックごとの音数、最高音を置く語、BPM の目安 |
| 改稿ログ | `v1 → v2` の形式で、どの行をなぜどう直したか |
| 作家視点メモ | どの技法をどこで使ったか |
| マスタリング指示 | 企画書から転記した、音圧などの基準 |

## かな版を作る理由

歌詞を2つ書くのは、Suno（歌詞とスタイルの説明文から歌入りの曲を作る AI）が漢字を読み間違えるためです。そこで、Suno に入力する歌詞は漢字をかなに開き、読みを指定しています。Stutter Step の冒頭は次のようになっています。

```text:260905_Stutter Step/LYRICS.md（表示用）
「あ、」の続きが 喉で渋滞
秒針の音だけ やたら でかい
つばを飲んで 三、二、一
```

```text:260905_Stutter Step/LYRICS.md（かな版）
「あ、」のつづきが のどでじゅうたい
びょうしんのおとだけ やたら でかい
つばをのんで さん、に、いち
```

2つの版は、行と内容を一致させて、読みだけを変えます。表示用は MV の歌詞表示に使い（第10章）、かな版は Suno が歌います。そのため、片方だけを改稿すると、画面に出る歌詞と実際に歌われる歌詞がずれてしまいます。

## 歌詞を機械で検査する

`LYRICS.md` を書いたら、`next.sh` の LYRICS 検査を通します。検査しているのは次の項目です。

- 表示用とかな版の2つの歌詞があるか
- かな版の漢字率が5%以下か
- 判定語（「正解」「勝ち」「負け」など）が無いか、一人称が4回以下か
- 指示語が0件か
- 表示用とかな版の行数が一致しているか
- 改稿ログに `v1 → v2` 形式の記録が2件以上あるか

かな版の検査では、見出しだけ「かな」と書いて中身が漢字のまま、という状態を弾くために、漢字の割合を実際に数えています。

```js:release/checklist.js
        if (blocks.length < 2) return '歌詞ブロックが2つ無い（表示用＋Suno投入用のかな版）';
        // ★かな版が本当にかな化されているか（見出しだけ「かな」と書いて漢字のままを弾く）
        const kana = section(md, 'かな');
        if (!kana || kana.length < 100) return 'かな版の本文が無い/短すぎる';
        const kr = kanjiRatio(kana);
        if (kr > 0.05) return `かな版に漢字が残っている（漢字率 ${(kr * 100).toFixed(1)}%）`;
```

判定語と一人称の検査は、僕が「あたし/そっちの番/正解が毎回入って浅い」と指摘したことから足しました。Skill にルールを書くだけでは読み飛ばせるので、検査で数えるようにしています。一人称の上限は、過去の曲で Frequency が15回、Prism が14回と多すぎたことを目安にしています。

改稿ログの件数を数えているのは、改稿ループを実際に回したことの記録にするためです。

```js:release/checklist.js
      const log = section(md, '改稿ログ');
      if (!log) return '改稿ログの節が無い（Step4 の改稿ループの証跡）';
      const rounds = (log.match(/v\d+\s*(?:→|->)\s*v\d+/g) || []).length;
      if (rounds < 2) return `改稿ログに改稿の記録が ${rounds} 件しか無い（v1→v2 形式で2件以上＝ループを回した証跡）`;
```

なお、判定語や指示語の検査は、ルールを決めた日より後に企画した曲にだけ適用しています。リリース済みの曲は音源が固定されていて直せないため、毎晩の監査（第14章）で違反として通知され続けないようにしています。

## 英語詞の場合

英語詞の曲（例えば Repeat Offender）では、かな版は作りません。英語詞は表示用の歌詞をそのまま Suno に入力します。

ただ、そのままでは LYRICS 検査が、英語詞には存在しない「かな版」を要求してしまいます。存在しない節を見出しだけ作って通すことはしたくなかったので、`release.json` に `"lyrics_lang": "en"` を書いた曲は、検査の内容を切り替えるようにしました。英語詞では、かな版の代わりに次の2つの節を要求します。

- **音節・強勢設計**：1つの音符に1音節を乗せ、強拍に強勢のある音節を置く設計
- **ライム設計**：韻の配置と、着地させる語からの逆算

## まとめ

歌詞は、コンセプトと裏設定を決め、小説を書いて削り、観点を変えた改稿ループで直して仕上げます。Suno が漢字を読み間違えるため、表示用とかな版の2つを書き、行数の一致や漢字率、改稿の記録を機械で検査しています。
