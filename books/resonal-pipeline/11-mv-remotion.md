## Remotion とは

Remotion は、React のコンポーネントとして書いた画面を、1フレームずつ描いて動画にするライブラリです。コンポーネントは「今が何フレーム目か」を受け取り、その時点の画面を返します。時間を引数にした関数として画面を書く、と考えると分かりやすいと思います。

![左がコード、右が Remotion のプレビュー。コードの1行が画面のどこに効くかを見ながら直す](/images/resonal-pipeline/remotion-code.jpg)
*左がコード、右が Remotion のプレビュー。コードの1行が画面のどこに効くかを見ながら直す*

この形にしている理由は、AI がコードを書き換えるだけで動画を直せるためです。動画編集ソフトの操作は AI にはできませんが、TypeScript のファイルなら Claude Code が読んで直せます。また、同じコードからは同じ動画が出るので、直した箇所以外が変わっていないことも確かめやすいです。

バージョンは曲ごとのプロジェクトで固定しています（最近の曲は `remotion` 4.0.481）。

### 1つのプロジェクトから3つを書き出す

1曲のプロジェクトには、コンポジション（Remotion で書き出す動画の単位）を3つ定義しています。

| コンポジション | 中身 | サイズ |
|---|---|---|
| `LyricVideo` | YouTube 本編 | 1920×1080（16:9） |
| `ShortVideo` | 縦長のショート動画 | 1080×1920（9:16） |
| `Thumbnail` | サムネイル（1フレームの静止画） | 1920×1080 |

Heat Shock の定義は次のとおりです。

```tsx:projects/heat-shock-snaptype-mv/src/Root.tsx
const SHORT_START = 113.0;
const SHORT_END = 144.19;

export const RemotionRoot: React.FC = () => {
  return (
    <>
      <Composition
        id="LyricVideo"
        component={LyricVideo}
        durationInFrames={Math.ceil(d.meta.duration * d.meta.fps)}
        fps={d.meta.fps}
```

ショートは本編と同じ歌詞データ（`lyrics.json`）を読み、指定した区間だけを0秒始まりにずらして描いています。歌詞や演出を直すと、本編とショートの両方に同じ直しが入ります。区間の終わり 144.19秒は、音源の低域を測って「キックが戻る直前」の位置を選んだ値です。

## スタイルパックは18の軸のプリセット

RESONAL の MV には、demonlord・snaptype・ricochet・negaposi など13のスタイルがあります。スタイルごとに Skill（`style-*`）やテンプレートがあり、歌詞の書体・出し方・画面の様式がひと通り入っています。

ただし、スタイルを選んでも見せ方の細部までは決まりません。見せ方は、歌詞（L）・キャラクター（C）・背景の面（F）・打点（H）の18の軸に分けていて、スタイルはその組み合わせの初期値（プリセット）という扱いです。第6章で書いた選定表では、18の軸を1つずつ埋めます。

例えば Heat Shock は snaptype を採用しましたが、次の軸を初期値から変えています。

| 軸 | 初期値 | Heat Shock |
|---|---|---|
| L2 書体 | 極太ゴシック | 明朝（NotoSerifJP 500） |
| C1 キャラの素材 | 静止画1枚 | 表情差分つきの静止画 |
| C3 フレーミング | 固定のバストアップ | 構図ジャンプ（カットで切り替える） |
| F2 背景の切り替え | 切り替えなし | セクションごと（白→赤→青→白） |
| F4 カメラ | ゆっくり移動 | 固定 |
| H2 打点の抜き方 | 暗転 | 単色の面へ飛ばす（赤） |

曲全体の既定値は `STYLE-SELECTION.md` に書き、シーンごとに変える軸は `DIRECTION.md` に `F4=固定` のような形で書きます。どちらもリリース用のチェックリストが記入を検査しています。

### 色と画像はソースに書かない

スタイルのコードには、曲固有の色や画像のファイル名を書かないようにしています。色はパレットとして1か所にまとめ、画像は `lyrics.json` などのデータから渡します。ソースに直接書くと、ある曲のために色を変えたとき、同じスタイルを使う別の曲まで色が変わってしまうためです。

ricochet の場合、色は `Ricochet.tsx` 冒頭の `PAL` だけで決まります。同じ ricochet でも、House Arrest はディープパープル、Cotton Overkill は白に近いパステルピンクで作りました。

```tsx:projects/cotton-overkill-ricochet-mv/src/Ricochet.tsx
export const PAL = {
  BG: '#fff2f7',      // ほぼ白のパステルピンク（高明度のベース）
  INK: '#2e0a24',     // 濃いベリーのインク＝ほぼ黒だが甘い側の色相を持つ（これが"凶器"）
  MAGENTA: '#ff2c9c', // ★唯一の高彩度アクセント
  PINK: '#ff7ac2',    // 図形/装飾用の中彩度ピンク（白地で沈まない濃さ）
  MINT: '#3fd8c8',    // ミント（寒色の受け）
  CYAN: '#00c8dc',    // 色収差ゴーストの寒色側（白地で見える濃さ）
  STROKE: '#ffffff',  // 文字の**白い**縁取り＝賑やかなパステル背景から濃いインクを分離
};
```

同じ理由で、キャラクターの動かし方もスタイルには組み込まず、後で説明する `puppet-rig` や `bounce-rig` という部品の側に置いています。スタイルの中に書くと、そのスタイルを使うときしか見えなくなり、別のスタイルの曲で使えなくなるためです。

## energy.json で背景を音に反応させる

背景の明るさや彩度を曲の盛り上がりに合わせるために、音源から `energy.json` という信号のファイルを作っています。作るのは `02_energy.py` で、動画の1フレームごとに2つの値を持ちます。

| 値 | 意味 | 動き方 |
|---|---|---|
| `sec` | セクションの強さ（0〜1） | 2.5秒の移動平均なのでゆっくり動く。Drop で高く、落ちサビで低い |
| `hit` | 打点（0〜1） | キックやスネアの立ち上がりで跳ね、数フレームで減衰する |

`hit` は、音量（RMS）がフレーム間で増えた量を正規化し、1フレームごとに 0.62 倍で減らしながら直前の値を保つことで作っています。

```python:projects/cotton-overkill-ricochet-mv/tools/02_energy.py
diff = [0.0]
for f in range(1, frames):
    diff.append(max(0.0, rms[f] - rms[f - 1]))
hit_raw = normalize(diff, 0.55, 0.995)
hit: list[float] = []
prev = 0.0
decay = 0.62  # 1フレームごとの減衰（打点を数フレーム保たせて見える打点にする）
for v in hit_raw:
    cur = max(v, prev * decay)
    hit.append(cur)
    prev = cur
```

Remotion 側では、フレーム番号で配列を引くだけの小さな関数を用意しています。

```ts:projects/cotton-overkill-ricochet-mv/src/energy.ts
type E = { fps: number; frames: number; sec: number[]; hit: number[] };
export const ENERGY = energy as E;

export function sampleEnergy(frame: number, offset = 0) {
  const i = Math.max(0, Math.min(ENERGY.frames - 1, frame + offset));
  return { sec: ENERGY.sec[i] ?? 0, hit: ENERGY.hit[i] ?? 0 };
}
```

Cotton Overkill では、`sec` で背景の白いもや（ウォッシュ）と彩度・コントラストを動かしています。静かな区間は白く飛ばし、サビでは白を 0 まで抜いて顔を見せます。

```tsx:projects/cotton-overkill-ricochet-mv/src/Stage.tsx
const wash = 0.22 * clamp01(1 - sec / 0.62);
const sat = 0.90 + sec * 0.34;
const contrast = 0.97 + sec * 0.12;
const bright = 1.05 - sec * 0.04;
```

サビでもやを抜いているのは、僕がレビューで「全編モヤ掛かりっぱなしは違う」と伝えたためです。また、最初は `hit` でカメラをズームさせていましたが、「サビでズンズン動くカメラワークもやめたい。かわりに彩瀬を動画素材として動かして」と伝えて外してもらいました。今は `hit` を綿がはじけるエフェクトにだけ使い、動きはキャラクターの側に持たせています。

## キャラクターの動かし方は、コストの低い順に検討する

彩瀬??の絵をどう動かすかは、C1（素材）と C2（動き）の軸で決めます。検討する順番は、コストの低い順と決めています。

| 順 | 方法 | コスト | 向いている曲 |
|---|---|---|---|
| ① | 静止画1枚（呼吸のような微動だけ） | 0 | 動かないこと自体が主題の曲 |
| ② | 表情差分を区間ごとに差し替える | 画像生成数枚 | 感情の変化を見せたい曲 |
| ③ | CSS のリグで動かす（puppet-rig / bounce-rig） | ほぼ0（レンダー時間だけ） | 踊る・跳ねるなど拍に乗る曲 |
| ④ | Kling で動画素材を作ってループさせる | 1本25クレジット（1080p・5秒） | コードで作れない動き（まばたき・髪） |

Kling は、1枚の画像から短い動画を作る生成サービスです。生成のたびにクレジットがかかり、動きも毎回同じにはならないので、コードで作れない動きにだけ使っています。

### 表情差分

Cold Read では、動画素材ではなく表情差分を数枚作って差し替える案を僕から出しました。曲の芯が「動かない低体温」だったので、Kling で常に揺らすより合っていると考えたためです。差分は横目・牙がのぞく笑み・伏し目の3枚だけにして、Drop などの打点で切り替えています。

表情については、おかわりアポカリプスのレビューで「0:12シーンの彩瀬の表情などがChatGPTって感じというかAIっぽい。もっと表情を作った方がAIぽさがなくなりそう」と伝えたことがあります。AI はこれを「左右対称・感情の記号がない・無難な微笑み」の3つに分解し、片目のウインクで非対称にする、眉に角度をつける、といった逆の指定で絵を作り直しました。

差分の画像は、顔だけを合成して作ります（`bounce-rig` の `face_swap.py`）。生成で「顔だけ変えて」と頼むと体や髪の輪郭まで動き（一致率88〜91%）、後で説明するリグの切り分けがずれるためです。合成なら透明度を元の画像から使うので、輪郭は動きません。

### puppet-rig：1枚の絵を関節で折る

`puppet-rig` は、1枚のキャラクター画像を紙人形のように関節で折って動かす部品です。同じ PNG を画面いっぱいに何枚も重ね、それぞれを `clip-path` で「胴」「頭」「腕」の形に切り抜き、関節の位置を中心に回転させます。

```tsx:.claude/skills/puppet-rig/templates/PuppetRig.tsx
const torsoRot = Math.sin(frame * 0.05) * 5 * gain; // body leans at the waist
const headRot = (-Math.sin(frame * 0.05) * 4 - k * 7) * gain; // counter-leans + nods on kick
const armRot = (Math.sin(frame * 0.09 + 1) * 9 + k * 13) * gain; // raised arm pumps hard on kick
const torsoSquash = 1 + Math.sin(frame * 0.07) * 0.03 - k * 0.05; // breathe + dip on kick
```

```tsx:.claude/skills/puppet-rig/templates/PuppetRig.tsx
<Part clip={CLIP.torso} ox={49} oy={49} rotate={torsoRot} scaleY={torsoSquash} z={1}>
  <Part clip={CLIP.head} ox={49} oy={20} rotate={headRot} z={3} />
  <Part clip={CLIP.arm} ox={46} oy={22} rotate={armRot} z={2} />
</Part>
```

頭と腕を胴の子要素にしているので、胴が傾くと頭と腕もついていき、そのうえで自分の関節でさらに曲がります。`k` は拍に合わせた値で、キックのたびに頭が頷き、腕が振られます。

切れ目が見えないように、回転の中心を部位の境目に置き、隣の部位と切り抜きを数%重ねています。これで20度を超えて回しても隙間が出ません。CSS だけで動くので、レンダーは1フレーム約2.2秒で済みます。

このリグでは、体全体を大きく揺らさないようにしています。全身が一緒に動くと関節の動きが埋もれ、「動いているのに動いて見えない」状態になるためです。書き出す前にフレーム差分の画像を作り、頭と腕だけが動いていることを確かめます。

### bounce-rig：拍に合わせて跳ねさせる

`bounce-rig` は、1枚の絵を拍に合わせて潰したり伸ばしたり（squash & stretch）して、跳ねているように見せる部品です。公開済みの曲では Bubble Trouble で使っています。

跳ねの数値は、僕が渡した「イラストが跳ねる動画の作り方」という解説動画から抜き出したものです。沈むときは横 100→102%・縦 100→92%、戻るときは横 103→100%・縦 95→100% と縦横比を変えます。そして、上がるときと下がるときでイージング（動きの速さの付け方）を変えています。

```tsx:.claude/skills/bounce-rig/templates/BounceRig.tsx
if (u < REC) {
  // 上げ: 潰れが**一気に**抜けて跳び出す。減速しながら頂点へ
  sq = 1 - easeOut3(u / REC);
  arc = easeOut2(u / REC);
} else if (u < REC + AIR) {
  // 頂点: ふわっと留まる（ここが「静」＝緩急の"緩"）
  sq = 0;
  arc = 1;
} else {
  // 下げ: ゆっくり落ち始めて**加速**し、着地の直前に一気に潰れる（＝"急"）
  const k = (u - REC - AIR) / ANT;
  sq = easeIn3(k);
  arc = 1 - easeIn2(k);
}
```

`u` は1拍の中の位置（0〜1）です。上げは一気に出て減速する ease-out、下げはためてから加速する ease-in にしています。上げと下げを同じカーブ（左右対称）にすると、1フレームあたりの変化量の「最大÷平均」が 2.2倍にとどまり、のっぺりした動きになりました。非対称にした今の形は 4.1倍です。この比を数値で測ってからカーブを決めています。

ほかに、次の規則を決めています。

- 部位は、接地→胴→頭→髪の順に1〜3フレームずつ遅らせて動かす（跳ねが下から上へ伝わって見える）
- 頭や胴を左右に振らない（跳ねと関係のない動きが入ると、首だけが勝手に回っているように見える）
- BPM と最初の拍の位置は、発注した値ではなく音源から測った値を使う

### Kling で動画素材を作る

Cotton Overkill では、先ほどのレビューを受けて、彩瀬??の基本の表情のときだけ Kling で作った微動のループ（まばたきと呼吸）を連番画像で再生しています。Static Hazard では、僕から「間奏だけKlingで作ろう」と伝えて、使う区間を絞りました。どちらも、最初と最後のフレームに同じ画像を指定して、元の絵に戻るループとして作っています。

### 3D：React Three Fiber

3D の世界をカメラで飛ぶ MV は、React Three Fiber（React で three.js を書くライブラリ）と `@remotion/three` で作っています。公開済みの曲では Poppy Requiem がこの方式です。

3D の作り方は Skill `render-3d-look` にまとめていて、主な規則は次のとおりです。

- 時間は `frame / fps` から計算し、three.js 側の経過時間では動かさない（同じフレームから同じ画が出るようにするため）
- 遠くの山や空は背景画にして、3D は光が複雑に絡む近景と主役にだけ使う
- 2D の絵と3D を同じカットに混ぜない（3D の中に板として置くと、回り込んだときに紙に見えるため）

## 演出の引き出し：mv-direction-library

カメラワークやエフェクトは、`mv-direction-library` という演出の辞書から選びます。2026年9月時点で、演出73件と、場所×光×演出のセット（シチュエーション）19件があります。

演出はカメラ・編集・ライティング・エフェクト・構図・モーション・UI の7つに分類していて、1件ごとに1つの Markdown ファイルです。ファイルの先頭には、検索しやすいように難易度・使用頻度・合う感情やタイミングを書いています。

```yaml:mv-direction-library/records/zoom-punch.md
name: ズームパンチ / Zoom Punch
slug: zoom-punch
category: [カメラ, 編集]
difficulty: 2
frequency: S
emotions: [衝撃, 高揚, 攻撃性, 狂気, 疾走感, 中毒性]
timing: [ドロップ, サビ, キメ, ビルドアップ, ラストサビ]
```

18の軸のうち、F3（画面エフェクト）と F4（カメラ）の選択肢はこの辞書を正本にしています。`DIRECTION.md` のシーン別の軸には、使った演出を `records/zoom-punch` の形で書き、チェックリストがファイルの実在を検査します。

辞書には自分の MV から起こした演出も入れています。例えば Ghosting Hour の、歌詞が語ごとに入れ替わり続ける出し方は `kinetic-swap-typography` として登録し、次の曲からも呼べるようにしました。

## カット割り：mv-cut-editing

カットの並べ方は、映像編集の基本的な考え方を学んで、Skill `mv-cut-editing` に編集の規則としてまとめています。例えば次のような規則があります。

- 区間の頭は、場所の引き→人→寄りの順に見せる
- 同じ被写体を同じサイズで続けない（ジャンプカットに見える）
- 引きは長く（3〜5秒）、寄りは短く（1〜3秒）。同じ長さのカットを並べない
- アップテンポの曲は、拍の頭で切る

規則のうち機械で判定できるものは、`cut_lint.py` で検査しています。レンダーの前に、エラーが0件になるまで直します。

```python:tools/cut_lint.py
MAX_FIX = 5.0        # 特別な意味がなければ1カット5秒を越えない
MAX_CLOSE = 3.0      # 寄り(C/X)は短く
MIN_WIDE = 1.2       # 引き(L)は読み解く時間が要る
MAX_POV = 6.0        # 主観は短く・特別な瞬間だけ
METRO = 4            # 同じ長さが4本続いたらメトロノーム
MAX_TILT = 2         # ダッチは1区間2本まで
```

## クレジット3点

RESONAL の MV には、次の3点のクレジットを入れています。

```
AI Vocal 彩瀬??
Produced by apoto
RESONAL
```

きっかけは、2026年8月10日に僕が「曲作成のMVの中で必ずクレジット表記を入れて欲しい。タイミングは任せる。skillなどに組み込んで、新曲作成およびMV作成時に必ず発動するように」と頼んだことです。クレジットがあったほうが、僕の好みだったためです。AI が過去の MV を調べると、表記がばらばらでした。`Ayase` とローマ字になっている曲、`Produced by` の by が抜けている曲があり、Prism や Ghosting Hour、Poppy Requiem などにはそもそも入っていませんでした。

そこで、文言は一字一句固定にして、出すタイミングと見た目だけをスタイルに合わせて変えてよい、というルールにしました。また、7つのスタイルのテンプレートにクレジットの部品（`Credits.tsx`）を組み込み、テンプレートをコピーした時点で3枚が出るようにしています。AI がやるのは、秒を曲に合わせることだけです。

### 文言は機械で検査する

文言が入っているかは `check-mv-credits.sh` で検査します。

```bash:tools/check-mv-credits.sh
has 'RESONAL'     '-F'  'RESONAL'      || missing+=('RESONAL')
has 'AI Vocal'    '-Fi' 'AI Vocal'     || missing+=('AI Vocal')
has '彩瀬??'      '-F'  '彩瀬??'       || missing+=('彩瀬??')
has 'Produced by' '-Fi' 'Produced by'  || missing+=('Produced by')
has 'apoto'       '-E'  "apoto[\"'<]"  || missing+=('apoto')
```

最初の版は `package.json` の説明文やコメント行にも反応し、中身がないのに OK を出していました。そこでコメント行を数えず、`apoto` は引用符やタグで閉じた表示用の文字列だけを数える形に直しました。

ただし、この検査はソースの文字列を見るだけで、画面に出ているかまでは保証しません。そのため、クレジット区間のフレームを原寸で書き出して目で確認する工程も残しています。

### 拍の頭に置く

クレジットの切り替えは、小節の頭（`60 / BPM * 4` 秒刻み）に合わせます。秒を勘で置くと、音から浮いて見えるためです。

既定は冒頭のイントロで3枚を順に出しますが、Heat Shock はイントロが1.38秒で歌が始まる曲だったので、キックが抜ける 66.5秒〜75.8秒の区間に置きました。3枚とも 3.1秒（BPM 154.74 の2小節）ずつです。

また、クレジットの背景に敷く帯（下スクリム）は、3枚のあいだ出しっぱなしにしています。Cold Read のときに、名前が変わるたびに帯が出たり消えたりして「点滅がうっとおしい」と僕が伝えたためです。

## まとめ

MV は Remotion で、本編・ショート・サムネイルの3つを1つのプロジェクトから書き出しています。スタイルは18の軸の初期値で、色や画像は曲ごとのデータから渡し、キャラクターの動かし方はスタイルとは別の部品に置いています。キャラクターはコストの低い順（静止画→表情差分→CSS のリグ→Kling）に検討し、演出とカット割りは辞書と文法から選び、クレジットは文言を機械で検査しています。次章では、組んだ MV をレンダーして検査し、僕がレビューするまでを説明します。
