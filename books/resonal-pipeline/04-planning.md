---
title: "企画 — 2〜3案から1つ選ぶ"
---

この章では、新曲の企画をどう進めているかを説明します。企画は6つの工程の1つ目で、人の番の1つ目でもあります。AI が案を2〜3本出し、人がその中から1つを選びます。

## 流れ

企画は、skill `planning` の手順に沿って次の順で進みます。

1. AI が `./next.sh --new` を実行し、直近の曲を確かめる
2. AI が「今回やってみたいことはあるか」を1問だけ聞く
3. AI が案を2〜3本出して止まる
4. 人が1つ選ぶ（混ぜたい点や変えたい点があれば、それも伝える）
5. AI が曲フォルダを作り、企画書 `BRIEF.md` を書く
6. AI が作った曲の一覧（`profile/ledger.md`）に1行足す

## 直近の曲を確かめる

「新曲を作りたい」と話しかけると、AI はまず曲名を付けずに `./next.sh --new` を実行します。すると、作った曲の一覧から直近3曲が表示されます。初めての曲では、一覧が空であることが表示されます。

```text
━━━ 新曲の企画 ━━━

【直近3曲（似た曲を続けない材料）】
  （profile/ledger.md が空＝初めての曲）

次: skill `planning` で案を2〜3出す → 人が選ぶ → ./next.sh --new "<Title>" → BRIEF.md に案と選んだ案を書く
```

このとき `./next.sh` は終了コード3（人の番）を返します。まだ曲名が決まっていないので、フォルダは作りません。

## 作った曲の一覧と被らないようにする

作った曲の一覧は、`profile/ledger.md` に1曲1行の表で残しています。

```markdown:profile/ledger.md
| タイトル | テンポ | ジャンル | ムード | 一行コンセプト |
|---|---|---|---|---|
```

AI は案を出すとき、この表の直近の曲と比べて、テンポ・ジャンル・ムードのうち2つ以上を変えるようにしています。似た曲が続かないようにするためです。台帳に載っていない曲も、`songs/` の各曲の `BRIEF.md` から拾います。

テンポの列には、企画の時点では BPM の目安を書きます。MV の工程で音源のテンポを実際に測ったら、その値に書き換えます。音源の生成サービスに BPM を指定しても、そのとおりのテンポの曲が出てくるとは限らないためです（「作曲」の章で説明します）。

また、会話の中で「次の曲はこうしたい」と話したことは、表の下に `- メモ: <内容>` の形で残しておきます。次の企画のとき、AI はこのメモを読み、「前にこう言っていましたが、どうしますか」と1行添えて聞きます。メモは企画で使ったら消します。

## 1問だけ聞いてから案を出す

案を出す前に、AI は次の1問だけを聞きます。

> 今回やってみたいことはありますか（テーマ・曲調・歌詞の言語・いつもと違う挑戦など）。無ければ『おまかせ』でOK

特にやりたいことが無ければ「おまかせ」で進められます。案を出す前に聞いておくのは、案を見てから条件が増えて、案を作り直すことを防ぐためです。

答えをもらったら、AI は `profile/` の音楽の傾向・世界観・歌い手・歌詞のこだわりを読み、案を2〜3本出します。各案には次の5つを並べます。

- 仮タイトル
- 一行コンセプト（この曲が一言で何か）
- ジャンル・テンポ（BPM の目安）・サビのムード
- 直近の曲との違い
- 歌詞の切り口（誰が・どんな場面で・何を言う曲か）

たとえば RESONAL の Dive Reflex では、一行コンセプトを「うるさい地上から息ひとつで消えて、音のない底を見て、何事もなかった顔で浮かんでくる。」と書いていました。ジャンルは liquid drum & bass、BPM の目安は174です。

## 案は2〜3本出し、人が選ぶ

案を1本に絞って持ってくることはしません。1案だけだと良いか悪いかしか言えませんが、2〜3案あると比べて選べるためです。

案を並べたら、AI は「どれにしますか。混ぜたい点や変えたい点があればそれも」と聞いて止まります。skill には「利用者の代わりに決めない」と書いていて、AI が自分で1つを選んで先に進むことはしません。

人が選んだら、AI は `./next.sh --new "<曲名>"` を実行します。これで `songs/<日付>_<曲名>/` のフォルダと、曲名や作成日を書いた `song.json` ができます。フォルダは手で作らず、このコマンドで作ることにしています。同じ曲名のフォルダがすでにあれば、作り直さずにそれを使います。

## 企画書 BRIEF.md

フォルダができたら、AI は企画書 `BRIEF.md` を書きます。後の作詞・作曲・MV の工程は、この企画書を元に進みます。

`BRIEF.md` は、大きく3つの部分でできています。

1. **候補**：並べた2〜3案（`### 案A: <タイトル>` の見出しで1案ずつ）
2. **選んだ案**：選ばれた案と、選んだ理由・人が足した注文
3. **選んだ案の中身**：コンセプト・サウンド・曲構成・歌詞への申し送り・ビジュアル

テンプレートの前半は次のとおりです。

```markdown:.claude/skills/planning/SKILL.md（BRIEF.md テンプレ）
## 候補
### 案A: <タイトル>
- <一行コンセプト> / <ジャンル・BPM・ムード>
### 案B: <タイトル>
- ...

## 選んだ案
- 案<X>: <タイトル>（選んだ理由・利用者が足した注文）

## コンセプト
- 一行コンセプト:
- 語り手・場面・時間帯:
- 直近の曲との違い:
```

続く「サウンド」にはジャンル・BPM の目安・ボーカルの声質と歌い方・楽器を、「曲構成」には各ブロックの役割を、「歌詞への申し送り」には言語・歌い手の一人称・入れたいモチーフや避けたい言葉を書きます。「ビジュアル」には、カバー画像と MV の方向（被写体・配色・背景・時間帯）を書きます。

選ばなかった案も、候補として企画書に残しています。会話の中で案を比べて選んだことは、そのままでは記録に残らないためです。

## ./next.sh の判定

企画の工程が終わったかどうかは、`./next.sh` が `BRIEF.md` の中身を見て判定しています。判定のコードは次のとおりです。

```js:engine/steps.js
    check(c) {
      const md = c.read(c.file('BRIEF.md'));
      if (!md) return ai('BRIEF.md が無い', 'コンセプト案を2〜3つ BRIEF.md に書く（各案は「### 案1 …」の見出し）');
      const plans = md.split('\n').filter((l) => /^#{2,4}\s.*案/.test(l) && !/選んだ案/.test(l));
      if (plans.length < 2) return ai(`案が ${plans.length} つ`, 'BRIEF.md に案を2つ以上並べる（「### 案1 …」「### 案2 …」）');
      const chosen = section(md, (l) => /選んだ案/.test(l));
      if (!chosen || !chosen.length) {
        return human('どの案にするか未決定', '案を人に見せて選んでもらい、BRIEF.md の「## 選んだ案」に結果と理由を書く');
      }
      return null;
    },
```

確かめているのは、次の3つです。

- `BRIEF.md` があるか
- 「案」を含む見出しが2つ以上あるか（1案だけで進めていないか）
- 「## 選んだ案」の節に中身があるか（人が選んだ結果が書かれているか）

3つ目が空のときは、`ai` ではなく `human` を返します。そのため、案が並んでいても選んだ結果が書かれていなければ、`./next.sh` は「★人の番」と表示して終了コード3で止まります。

```text
次の1手（1/6 企画・skill `planning`）: ★人の番
  現状: どの案にするか未決定
  やること: 案を人に見せて選んでもらい、BRIEF.md の「## 選んだ案」に結果と理由を書く
```

このように、選んだ結果を企画書の見出しに書き、それを `./next.sh` で確かめるようにしています。BRIEF.md のテンプレートで見出しの語を変えないよう指示しているのも、この判定が見出しを手がかりにしているためです。

## まとめ

企画では、AI が直近の曲を確かめ、1問だけ聞いてから案を2〜3本出し、人がその中から1つを選びます。案は作った曲の一覧と比べて、テンポ・ジャンル・ムードのうち2つ以上を変えるようにしています。選んだ案は `BRIEF.md` にまとめ、`./next.sh` は案が2つ以上あるか、選んだ結果が書かれているかを見て、次の工程に進むかを判定します。
