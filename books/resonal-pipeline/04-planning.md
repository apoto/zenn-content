---
title: "企画 — 案を出して、1つ選ぶ"
---

この章では、新曲の企画をどう決めているかを説明します。企画は、僕が判断する3か所のうちの1つ目です。

## 流れ

企画は次の順で進めます。

1. `next.sh --new` を実行し、企画の材料を表示する
2. AI が僕に「今回やりたい表現はあるか」を1つだけ聞く
3. AI がコンセプトを2〜3案出す
4. 僕が1つ選ぶ
5. AI が企画書 `BRIEF.md` を書く

## 企画の材料を表示する

新曲を始めるときは、曲名を付けずに `next.sh --new` を実行します。

```bash
./release/next.sh --new
```

すると、次の3つが表示されます。

- **直近3曲の曲調**：似た曲を続けないために、最近の曲の BPM やジャンルを見せる
- **僕に聞くこと**：「今回やりたい表現・イレギュラーはある？」の1問だけ
- **以前の要望**：会話の中で僕が「次はこうしたい」と言ったことのメモ

このコマンドは、表示だけしてフォルダは作りません。案を出す前に僕に聞くことで、後から条件が増えて案を作り直すことを防いでいます。

以前の要望は「参考」として表示するだけにしています。そのとき言ったことが今も生きているとは限らないので、AI には「前にこう言ってたけど、どう？」と軽く聞くよう指示しています。

## 似た曲を続けないための台帳

RESONAL では、これまでの曲の曲調を、1曲1行の表（曲調台帳）にまとめています。記録しているのは次の5項目です。

| # | 項目 | 例 |
|---|---|---|
| ① | BPM帯 | 速（174） |
| ② | サブジャンル | liquid drum & bass |
| ③ | サビのムード | 静けさへ沈む快 |
| ④ | ボーカル | 可愛い高音、水中は母音を伸ばす |
| ⑤ | 構成 | 息を吸う音で始まり、息継ぎで切る |

新曲の案は、直近の曲とこの5項目のうち2項目以上を変えるようにしています。特にサビのムードとサブジャンルを優先して変えます。

BPM は、発注した値ではなく、できあがった音源から測った値を記録します。Suno に BPM を指定しても、実際に出てくる曲のテンポは違うことがあるためです。

## 案を出して、選ぶ

案は、Skill `song-concept-jp` の手順に沿って2〜3本出します。1案だけを持ってくることはしません。1案だけだと、僕は良し悪ししか言えませんが、2〜3案あると比べて選べるためです。

僕は、その中から1つを選びます。ここは往復せず、1回で決めるようにしています。

## 企画書 BRIEF.md

選んだ案をもとに、AI が企画書 `BRIEF.md` を書きます。後の工程（作詞・作曲・MV）は、この企画書を元に進みます。

`BRIEF.md` には、次の節を書きます。

- コンセプト
- サウンド設計
- 曲構成
- キャラクターの声
- 作詞への申し送り
- ビジュアル指針
- マスタリング指示
- 案出し（並べた2〜3案と、選んだ理由）
- 今回の縛り（僕に聞いた「今回やりたいこと」）

## 企画書を機械で検査する

`BRIEF.md` は、書いたかどうかではなく、中身があるかどうかを検査しています。各節に最低限の文字数があるか、案出しの節に2案以上あるか、今回の縛りの節があるかを確認します。

```js:release/checklist.js
const need = [['コンセプト', 60], ['サウンド設計', 80], ['曲構成', 60],
              ['キャラクター', 40], ['作詞への申し送り', 60], ['ビジュアル指針', 40], ['マスタリング指示', 40]];
const miss = need.filter(([kw, min]) => !filled(md, kw, min)).map(([kw]) => kw);
if (miss.length) return `節が無い/中身が薄い: ${miss.join(' / ')}`;
```

案出しと今回の縛りの節を検査しているのは、会話の中でやったことは記録に残らないためです。「2〜3案を出して選んだ」「今回やりたいことを聞いた」ということを企画書に書かせて、それを機械で確かめています。

あわせて、曲調台帳に新曲の1行が追加されているかも検査しています。追加を忘れると、次の曲で「似ていないか」を判断できなくなるためです。

## まとめ

企画は、`next.sh --new` で材料を出し、僕に1つだけ聞いてから、AI が2〜3案を出して僕が選ぶ、という流れです。選んだ案は `BRIEF.md` にまとめ、中身があるかを機械で検査しています。
