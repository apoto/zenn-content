---
title: "はじめ方とセットアップ"
---

この章では、公開版のワークフローを使い始めるときの流れを説明します。リポジトリを手元に置く方法、セットアップで聞かれること、使う外部サービスの選び方、そしてRESONALとは違うジャンルの音楽に置き換える方法を順に見ていきます。

## Claude CodeかCodexに頼んで始める

使い始めるときは、Claude CodeかCodexを開いて、次のように頼みます。

```text
https://github.com/apoto/resonal-workflow
このリンク先のワークフローを使って、AI と一緒に曲を作りたいです。
手元に取り込んで、セットアップから始めてください。分からないことは質問してください。
```

するとAIがリポジトリをクローンし、中の `CLAUDE.md`（Codexの場合は `AGENTS.md`）を読みます。`CLAUDE.md` の最初の節には、次のように書いています。

```markdown:CLAUDE.md
## 0. 最初にやること
- **`profile/` が無い** → skill `setup`（`.claude/skills/setup/SKILL.md`）を始める。利用者が「セットアップして」と言っていなくても、作業の前に始める。
- **`profile/` がある** → 利用者が「新曲を作りたい」「新曲作成」と言ったら skill `new-song` を始める。作りかけの曲は `./next.sh --list` で探して再開する。
```

クローンした直後は `profile/`（作りたい音楽や歌い手の設定を置くフォルダ）がまだ無いので、AIはセットアップの手順（skill `setup`）を始めます。最初に「これから道具の確認 → 10ほど質問 → 設定ファイル作成、の順で進めます」と伝えてから、1つずつ進めていきます。

## 道具を確かめる

セットアップの最初に、AIは `tools/check_env.sh` を実行して、必要な道具が入っているかを確かめます。必須の道具は、Node.js・Python・numpy・ffmpeg・Whisper（音声の文字起こしをする道具。MVで歌詞を出すタイミングを取るのに使います）です。結果は、道具ごとにOKかNGかの一覧で表示されます。

足りない道具があれば、AIは入れ方を示し、入れてよいかを1つずつ聞きます。了承を得る前には入れません。`sudo` が要るコマンドは、パスワードをAIに渡さないよう利用者に実行してもらいます。入れ終わったら `tools/check_env.sh` をもう一度実行し、必須の道具が揃ったことを出力で確かめてから次に進みます。

## ヒアリングで聞かれること

道具が揃ったら、AIが作りたい音楽について質問します。聞き方には、次の決まりを設けています。

- 1回に1問だけ聞き、答えの例を2〜3個添える
- 分からなければ「あとで決める」で先に進める（その項目は「未定」と書いておき、後から埋められる）
- 答えを1行に要約して復唱してから、次の問いに進む

質問と、答えが書き込まれる場所は次のとおりです。

| # | 聞かれること | 答えの例 | 書き込み先 |
|---|---|---|---|
| Q1 | 作りたい音楽の傾向（ジャンル・ムード・テンポ感） | 「夜の街のシティポップ、ゆったり」「速くて激しい音ゲー曲」「ピアノのバラード」 | `profile/sound.md` |
| Q2 | テーマ・世界観 | 「都会の孤独と小さな救い」「放課後の青春」 | `profile/world.md` |
| Q3 | 歌い手・キャラクター（名前・一人称・性格・話し方・見た目・立ち絵の有無）と、歌声のイメージ | 「ミナト・私」「銀髪ボブ・黒いパーカー」「若い女性の澄んだ声」 | `profile/character.md`・`profile/sound.md` |
| Q4 | 歌詞の言語と作風のこだわり（任意） | 「日本語、サビに英語を少し」「使いたくない言葉がある」 | `profile/lyrics.md` |
| Q5 | ユニット名とクレジットの表記 | 「MOONLIT LANE／Vocal: ミナト／Produced by自分の名前」 | `workflow.config.json` |
| Q6 | 音の大きさ（`streaming` か `loud`） | 迷ったら `streaming` | `workflow.config.json` |
| Q7 | 使う外部サービス（音源・画像・動画素材・通知） | 「Suno」「自分で用意する」「使わない」 | `workflow.config.json` |
| Q8 | どこにリリースするか（複数選べる） | 「YouTubeだけ」「YouTubeと配信サービス」「リリースしない」 | `workflow.config.json` |

Q3は、キャラクターがいるかどうかを最初に聞き、いる場合だけ名前や見た目を続けて聞きます。キャラクターがいない、声だけの曲にもできます。立ち絵の画像がある場合は、その置き場所を伝えると `profile/images/character.png` に置かれ、カバー画像の生成やMVで見た目を揃えるのに使われます。

Q6の音の大きさは、マスタリングの目標値になります。`streaming` は配信サービス向けの控えめな音量（-14 LUFS）で、`loud` は音圧を強めにした設定（-9.5 LUFS）です。LUFSなどの単位は「マスタリング」の章で説明します。

Q8では、YouTube・配信サービス（Spotify・Apple Musicなど）・それ以外（SoundCloudなど）から、リリース先を選びます。作って手元に置くだけなら「リリースしない」も選べます。リリース準備の工程では、選んだ先の分だけ素材と文面を作ります。配信サービスに出す場合は、MVのクレジットとは別に、配信で使う作詞・作曲の名義も聞きます。

## profile/ とworkflow.config.jsonができる

ヒアリングが終わると、AIは答えをもとに次のファイルを書きます。

- `profile/sound.md`・`world.md`・`character.md`・`lyrics.md`：Q1〜Q4の答え
- `profile/ledger.md`：作った曲の一覧（最初は空の表）
- `workflow.config.json`：ユニット名・クレジット・音量の目標・使う外部サービス・リリース先

書いたあとは、`node engine/config.js providers` と `node engine/config.js release` で設定ファイルが読めること（JSONの書き間違いや選べない値が無いこと）を確かめます。そのうえで、AIがファイルの中身を利用者に見せ、OKが出るまで直してから確定します。

キャラクターがいる場合は `CLAUDE.md` の人格の節も書かれ、以降の会話ではAIがそのキャラクターの口調で話すようになります。RESONALで彩瀬??と会話しながら制作しているのと同じ形です。

最後にMVのテンプレートの依存パッケージを入れて、セットアップは終わりです。次からは「新曲を作りたい」と話しかけると、企画から始まります。設定を変えたくなったときは、「キャラを変えたい」「音の大きさを変えたい」などと頼むと、AIが該当するファイルを直します。

## 使う外部サービスと置き換え

このワークフローでは、音源・画像・動画素材・通知に外部サービスを使います。これらは有料のプランやクレジットが要ることがあるため、用途ごとに `workflow.config.json` の `providers` で選べるようにしています。セットアップのQ7では、推奨と選択肢を並べて1つずつ聞かれます。

![使うサービスは選べる](/images/resonal-pipeline/tools.png)
*推奨はあるけれど、セットアップで自分の使いたいものに置き換えられる*

```json:workflow.config.example.json
  "providers": {
    "music": { "use": "suno", "note": "" },
    "image": { "use": "codex", "note": "" },
    "video": { "use": "none", "note": "" },
    "notify": { "use": "none", "note": "" }
  },
```

| 用途 | 推奨 | 選べる値 | 使われる場面 |
|---|---|---|---|
| `music` 作曲 | Suno（`suno`） | `suno` / `other` / `manual` | 音源の生成。どれを選んでも生成は人が行い、WAVを置く |
| `image` 画像 | codex CLI（`codex`） | `codex` / `other` / `manual` | カバー画像（ジャケットやサムネイルの元）。窓口は `tools/gen_image.sh` |
| `video` 動画素材 | Kling MCP（`kling-mcp`） | `kling-mcp` / `other` / `none` | MVの背景を動かすループ動画（任意）。`none` なら背景はカバーの静止画 |
| `notify` 通知 | Slack（`slack`・任意） | `slack` / `none` | できたMVを自分のSlackのチャンネルで受け取る |

推奨以外の値は、次の意味です。

- `other`：推奨以外のサービスを使います。`note` に使い方を1行で書くと、AIはその内容に従います。画像をコマンドで作れる場合は、`cmd: mytool gen --prompt {prompt} -o {out}` のように書くと、`tools/gen_image.sh` が `{prompt}` などを置き換えて実行します。「MCPのxxxの画像生成を使う」「Udioで作ってwavを置く」のように、言葉で書くこともできます
- `manual`：人が自分で用意します。AIはプロンプトや文章を渡して待ちます
- `none`：その工程を飛ばします

決められないときは、AIが `manual` か `none` を勧めます。あとから「画像生成を別のサービスにしたい」と頼めば変えられます。

また、外部サービスで生成や送信をする前には、AIが利用者に確認を取ります。失敗しても自動では再実行せず、エラーをそのまま伝えて、再実行するかを利用者に決めてもらいます。外部サービスでは、失敗した試行も課金や回数制限の対象になりうるためです。

料金と利用条件はサービスごとに異なり、変わることもあります。そのため、この本でも金額は書いていません。使う前に、各サービスの料金ページと規約を確認してください。

## 音ゲー曲以外にも置き換えられる

RESONALは、音ゲーのようなハイエナジーな曲を中心に作っています。一方で、公開版のワークフローにはRESONALのジャンルや彩瀬??の設定は入っていません。企画・作詞・作曲の各工程は、`profile/` に書かれた内容を読んで動くので、`profile/` を変えればバラードでもアニソンでも同じ流れで作れます。

記入例として、リポジトリには `profile.example/` を入れています。これは、夜の街のシティポップを作る架空のユニット「MOONLIT LANE」の設定です。音楽の傾向を書いた `sound.md` は、次のようになっています。

```markdown:profile.example/sound.md
## ジャンル
- 中心: シティポップ（80年代風のコード感 × 今のクリアな音）
- 隣: ネオソウル・フューチャーファンク・ローファイ寄りのミドルバラード

## ムード
- 夜の街の少し寂しいけれど温かい空気。踊れるけれど騒がない
- サビは開放感、Aメロは淡々と

## テンポ
- 80〜120 BPM が中心。ときどき 125 前後の四つ打ち
```

ほかのファイルにも、同じユニットの設定が入っています。`world.md` には架空の湾岸の街「白波町」と夕方から明け方までの時間帯、`character.md` には歌い手「ミナト」の一人称や話し方、`lyrics.md` には「指示語を使わない」「奇跡・運命・永遠は使わない」といった作風の決まりを書いています。

この設定で「新曲を作りたい」と話しかけると、企画の案は80〜120 BPMのシティポップの範囲で出され、歌詞は白波町を舞台に、ミナトの一人称で書かれます。Sunoに貼る文章にも、`sound.md` の「近い距離で、息の混じったやわらかい声」が反映されます。工程の進め方はRESONALと同じで、変わるのは `profile/` から読まれる中身です。

## まとめ

公開版のワークフローは、Claude CodeかCodexにリポジトリのURLを渡し、クローンとセットアップを頼むところから始まります。AIが道具を確かめ、1問ずつのヒアリングで作りたい音楽・歌い手・使う外部サービスを聞き、`profile/` と `workflow.config.json` を書きます。外部サービスは推奨を示したうえで、ほかのサービスや手作業にも置き換えられます。`profile/` を書き換えれば、RESONALとは違うジャンルの音楽にも同じ流れで使えます。
